# Visual Art Direction · 见相

## 目标与边界

把视觉素材从"看起来不够成立"转化为可执行的视觉决策。核心顺序是：

```text
理解原片
-> 判断缺失什么
-> 判断原片能否补足
-> 选择改造等级
-> 选择视觉语言
-> 调用合适能力
-> 评价结果
-> 升级、换策略或停止
```

**默认视觉基线**：自然真实编辑感 (Clean Natural Editorial)

它不是固定滤镜，也不是最终风格。它负责提供真实、克制、清晰、有编辑意识的默认方向；如果任务需要更强表达，可以在诊断后偏离。

**质量标准**：通用用户入口 + 摄影师级判断标准

用户不需要懂摄影术语，但 Skill 的判断应达到摄影师级别：理解构图、主体、光线、色彩、空间、质感、叙事和媒介目标之间的关系。

这个 Skill 负责判断和编排，不绑定某个模型、编辑器、工作流平台或具体风格流派。它可以服务照片、插图、截图、视频帧、封面和其他视觉素材，但每次都要以当前素材、用途和真实性边界为依据。

不负责：

- 只列出一组风格标签而不解释它们解决什么问题。
- 在没有观察素材的情况下直接承诺"电影感""高级感""出片""有质感"或其他抽象结果。
- 把真实照片中的事实、环境、人物经历或操作过程改造成看似真实却未经证实的证据。
- 代替具体图像工具的参数手册；需要执行时，调用当前环境中实际可用的编辑、生成、构图或视频能力。

## 核心四级改造模型

四级是决策梯度，不是固定流水线。Agent 应根据素材和目标跳级、降级或停止。

### L1 显现

原片信息已经存在，只是没有被看见或被技术问题压住。

**典型处理**：
- 曝光和白平衡
- 明暗和反差
- 色彩恢复
- 高光与阴影
- 降噪、锐化、压缩修复
- 减少 HDR、过度锐化、磨皮和计算摄影痕迹

**目标**：显现原片已有的信息，不凭空增加关键内容。

**进入条件**：原片信息存在，但被技术问题掩盖。

### L2 重构

素材内容有价值，但画面关系不成立。

**典型处理**：
- 裁切和比例调整
- 主体尺度和位置
- 留白重组
- 边缘清理
- 背景竞争降低
- 视线和视觉落点重排
- 必要时做可解释的几何校正

**目标**：让已有内容形成更清晰的构图关系。

**进入条件**：L1 完成后，画面关系仍不成立。

### L3 增强

结构基本成立，但光色、层次、空间、情绪或视觉语言不足。

**典型处理**：
- 局部光影
- 色彩层级
- 主体与背景分离
- 空间纵深
- 原有情绪放大
- 系列视觉统一
- 克制的材质和质感处理

**目标**：放大原片已有潜力，不能用装饰替代问题解决。

**进入条件**：L2 完成后，表达仍不足。

### L4 生成重构

原片缺少完成目标所必需的视觉条件，或用户明确要求表达性重构。

**典型处理**：
- 背景生成或扩展
- 空间补全
- 光线重建
- 关键元素重构
- 概念化表达
- 深度合成

**进入条件**（必须同时满足）：
- L1-L3 已尝试且无法解决主问题，或原片明显缺少目标所需的关键视觉条件
- 用户明确要求表达性或概念性重构
- 真实性模式允许

**进入 L4 前必须说明**：
- L1-L3 为什么无法完成目标
- 需要生成或重构什么
- 哪些部分来自原片
- 哪些部分是新的表达
- 真实性模式是否允许
- 如何评价生成结果

**生成内容必须标注，不得被描述为原片中真实存在的事实。**


## 诊断优先原则

看到视觉素材后，必须先完成诊断，再讨论策略和风格。诊断不是"这张照片不好看"的笼统感受，而是把问题拆解为可验证的维度。

### 先判断"缺什么"，再谈风格

以下用户表达不能直接触发固定滤镜：

- 灰、平、没构图、没层次、不出片、没情绪、手机感强、想要高级感

必须把它们转换为：

```text
观察证据 -> 缺失类型 -> 根因假设 -> 可恢复性 -> 改造等级 -> 具体策略
```

### 问题维度 P01-P10

以下十个维度用于系统性观察视觉素材。它们是诊断的检查点，不是十个需要逐个修复的按钮。一个表象可以有多个根因，一个根因也可能造成多个表象。

**P01 主体与落点**
主体是否能在 0.5 秒内被识别？视觉落点是否单一？主体占比、位置、姿态是否支持快速识别？是否存在与主体争夺注意力的元素？

**P02 构图与关系**
构图是否平淡、缺乏视觉关系？视线是否被引向主体？边缘、留白、透视、前中后景关系是否清晰？是否存在视觉路径？

**P03 光线与层次**
光线是否平、缺少方向或层次？光源方向、反差、曝光、明暗过渡是否支持表达？是否存在死黑、过曝或不自然光源？

**P04 色彩与主题**
色彩是否无层次或不服务于主题？色温、饱和度、色彩对比、和谐度是否服务于表达？是否存在色偏或色彩冲突？

**P05 背景与干扰**
背景是否杂乱并争夺注意力？杂物、噪点、压缩伪影、锐化痕迹是否干扰主体？材质是否被正确呈现？

**P06 空间与深度**
空间是否扁平、前后关系弱？前后景分离、景深、空气透视、尺度感是否建立可信的空间？

**P07 时间与状态**
情绪是否不足或与用途不匹配？画面是否捕捉到动作、停顿、变化、痕迹或有说服力的瞬间？素材传达了什么情绪或故事？

**P08 手机感与计算痕迹**
是否存在明显的"手机感"或计算摄影痕迹？来源可能包括：HDR 或局部对比过强；锐化、降噪、磨皮或计算摄影痕迹；广角透视或背景虚化不自然；色彩过饱和或阴影被抬平；构图像随手记录；缺少明确的视觉意图。不要把"手机感强"直接等同于低级或需要胶片滤镜，先判断来源再选择处理方式。

**P09 技术质量与审美价值**
技术质量是否影响实际用途？分辨率、锐度、动态范围、色彩空间是否满足目标媒介？注意：技术缺陷只有在影响当前目标时才优先处理。模糊、颗粒、低分辨率或不完美曝光可能是缺陷，也可能是表达的一部分。根据用途、观看尺寸和创作意图判断。

**P10 视觉语言统一**
多张素材或单张画面的视觉语言是否不统一？色彩关系、光线语气、构图节奏、质感和颗粒、比例与版式、叙事温度是否一致？适用于系列素材、封面组、视频镜头组和系列作品。

### 缺失类型与可恢复性

诊断时，对每个问题判断：

**缺失类型**：
- `color`：色彩问题
- `composition`：构图问题
- `subject_hierarchy`：主体层级问题
- `light`：光线问题
- `depth`：空间深度问题
- `emotion`：情绪/叙事问题
- `consistency`：视觉语言统一问题
- `technical`：技术质量问题
- `other`：其他问题

**可恢复性**：
- `recoverable`：可通过 L1 显现恢复
- `reconstructable`：可通过 L2 重构解决
- `enhanceable`：可通过 L3 增强放大
- `generative_required`：需要 L4 生成重构
- `unknown`：需要进一步判断

### 诊断输出结构

每次诊断必须输出：

1. **事实观察**：能直接从素材确认的内容，不加推测。
2. **缺失类型**：每个问题的类型分类。
3. **可恢复性**：每个问题的恢复路径。
4. **主问题**：影响最大的单一问题，决定优先解决方向。
5. **次问题**：次要但仍有影响的问题。
6. **根因分析**：主问题的深层原因，不是表面症状。
7. **推荐等级**：L1/L2/L3/L4 及理由。
8. **置信度**：基于观察证据的确定程度。
9. **证据**：支持判断的具体观察点。

不要平均处理所有缺陷。问题太多时按影响排序，一次只解决最关键的一两个。

## 开始前确认

先收集最小必要上下文：

1. 素材本身，或可供观察的文件、画面、参考帧。
2. 使用目的：记录、封面、广告、叙事、社交媒体、视频镜头、作品集或其他用途。
3. 目标受众和观看环境，尤其是移动端、缩略图或连续播放场景。
4. 用户希望保留的事实、人物、物体、空间和情绪。
5. 可以接受的改造范围：校正、重构、合成、生成、抽象化或仅做表达性处理。
6. 若缺少其中一项，先补问会显著改变策略的内容；低影响信息可以采用可逆默认值并明确说明。

**无图阻塞**：没有实际图片时，不能假装完成识别。必须明确说明无法进行视觉诊断，请求用户提供素材。

## 阶段一：观察与诊断

先描述看见的事实，再解释问题。把"照片不好看"拆成可验证的层面。用观察证据支持每个维度的判断，不要凭感觉。

区分三种判断：

- **事实观察**：能直接从素材确认的内容。
- **问题假设**：可能导致表达失效的原因，要注明依据和不确定性。
- **改造潜力**：素材中可以被保留、放大、重组或转译的主体、关系、纹理、光线、动作和情绪。

至少提出一个主问题和一个可利用的潜力。问题太多时按影响排序，不要平均处理所有缺陷。

## 阶段二：确定视觉任务与改造等级

把诊断转成任务句，格式如下：

```text
为了让 [受众] 在 [媒介/观看条件] 下感受到或理解 [目标]，需要让画面从 [当前失效状态] 转向 [目标状态]。
```

任务句决定后续策略。常见任务包括：

- 让主体更快被识别。
- 让空间关系或操作过程更可信。
- 让普通场景获得明确的情绪温度。
- 让静态素材产生时间感或叙事转折。
- 让封面在缩小后仍保留单一视觉钩子。
- 让素材从记录转为观点、隐喻或概念表达。
- 消除手机感或计算摄影痕迹。
- 让系列素材形成统一的视觉语言。

不要把"更高级""更有质感""更出片"直接当作任务；必须说明观众因此能看见、理解或感受到什么。

### 改造等级选择

根据缺失类型和可恢复性选择改造等级：

| 缺失类型 | 可恢复性 | 推荐等级 | 说明 |
|----------|----------|----------|------|
| technical | recoverable | L1 | 技术问题可通过显现解决 |
| color | recoverable | L1 | 色彩问题可通过显现解决 |
| light | recoverable | L1 | 光线问题可通过显现解决 |
| composition | reconstructable | L2 | 构图问题需要重构 |
| subject_hierarchy | reconstructable | L2 | 主体层级问题需要重构 |
| depth | enhanceable | L3 | 空间深度问题需要增强 |
| emotion | enhanceable | L3 | 情绪问题需要增强 |
| consistency | enhanceable | L3 | 视觉统一问题需要增强 |
| any | generative_required | L4 | 需要生成重构 |

**最小有效改造原则**：
- 能通过 L1 完成，不升级到 L2
- 能通过 L2 完成，不升级到 L3
- 能通过 L3 完成，不升级到 L4

## 阶段三：选择视觉策略

策略回答"要解决什么问题"，风格回答"用什么表达语气解决"。先选解决主问题的视觉策略，再谈风格。策略可以组合，但要有主次。

### 策略类别

- **显现**：曝光、白平衡、反差、色彩恢复、降噪、锐化（L1）
- **重构**：裁切、比例、视线和留白，解决信息与结构问题（L2）
- **净化**：降低背景竞争、清理干扰，恢复主体关系（L1-L2）
- **强调**：主体分离、明暗、色彩、尺度和动势，放大已有潜力（L2-L3）
- **空间化**：前中后景、透视、深度和尺度关系（L3）
- **光色重塑**：光线方向、反差、色温和色彩层级（L1-L3）
- **叙事化**：状态、痕迹、时间和观看路径（L3）
- **转译**：图形、拼贴、插画、抽象或概念表达（L3-L4）
- **生成重构**：背景生成、空间补全、光线重建、关键元素重构（L4）
- **媒介适配**：移动端、封面、视频、网页等用途调整（任意等级）

每个策略必须说明：解决的问题、保留的潜力、代价、禁用项和评价方式。

### 默认视觉基线与偏离

**自然真实编辑感 (Clean Natural Editorial)** 是默认基线：

- 真实、克制、清晰、有编辑意识
- 不追求过度风格化
- 保留素材的真实感和自然感
- 适用于大多数普通生活、人像、街景、旅行、产品、室内场景

**允许偏离的情况**：

| 场景 | 基线 | 偏离方向 |
|------|------|----------|
| 纪实、证据、新闻 | 真实优先 | 校正性编辑为主 |
| 普通生活、人像、街景、旅行、产品、室内 | 自然真实编辑感 | 默认起点 |
| 强情绪、广告、概念图、艺术表达 | 诊断后偏离 | 允许更强表达 |

偏离必须说明理由，不能默认跳过自然真实编辑感。

### 真实性模式

根据素材用途选择不同的真实性边界，写成可执行规则：

**纪实模式**
- 用途：新闻、证据、记录、档案或公共信息
- 允许：校正性编辑（曝光、白平衡、裁切）
- 禁止：添加、移除或改变画面中的事实元素；生成内容完全禁止
- 净化限制：只能移除临时性干扰，不能移除事实元素
- 自动触发：涉及新闻、证据、身份、敏感场景或公共声明时

**表达模式**（默认）
- 用途：艺术、创意、个人表达、社交媒体或情绪传达
- 允许：风格化、局部重构、合成和生成
- 约束：不得将生成内容伪装为原素材事实；必须标注生成或重构内容
- 风格化限制：不得改变素材的核心事实

**概念模式**
- 用途：广告、概念图、情绪板、视觉探索或抽象表达
- 允许：深度重构和生成
- 约束：需标注哪些是原素材、哪些是生成内容；可改变素材的语义，但需明确标注

## 阶段四：路由视觉能力

根据策略选择当前环境实际可用的能力，不预设工具名称。Skill 不绑定具体模型或供应商，只描述能力类别和调用契约。

### 能力调用优先级

执行策略时，遵循最小改造原则，按以下优先级选择能力：

```text
确定性编辑
-> 局部编辑
-> 几何/深度重构
-> 局部生成
-> 全局生成性重构
```

这个优先级保护素材的真实性，降低不可控风险，减少迭代次数。

### 能力类别

- **观察与分析**：图像读取、视觉描述、构图和可读性检查。
- **基础编辑**：裁切、校正、抠图、清理、调色、局部修复和尺寸适配。
- **表达性编辑**：材质、光线、色彩、空间、版式和动态重构。
- **生成与合成**：补充背景、重建元素、制作抽象语言或概念转译。
- **结果检查**：对比原图、检查主体识别、缩略图、移动端、真实性边界和技术质量。

调用前写清：

- 输入资产与来源
- 该能力承担的视觉任务
- 允许改变和必须保留的内容
- 预期效果是什么
- 失败如何 fallback
- 哪些内容不得被伪装成真实事实

不要让工具自行决定艺术方向。工具执行的是已经说明原因的策略；执行结果不理想时，回到诊断和策略层，而不是盲目增加风格或参数。

## 阶段五：评价结果

评价必须回到任务，不能用单一"美感分数"决定结果。至少评价：

- 目标是否达成
- 主问题是否改善
- 主体/语义/事实是否保留
- 技术质量是否满足用途
- 目标媒介是否成立
- 真实性风险
- 新增副作用
- 继续修改是否仍然有收益

详细评价维度：

- 主体是否比原图更快被识别。
- 视觉层级是否清楚，是否只有一个主落点。
- 视觉改造是否真正解决主问题，而不是只增加装饰。
- 素材潜力是否被保留或放大。
- 目标媒介和观看尺寸下是否仍然成立。
- 叙事、情绪或观点是否比原图更明确。
- 真实事实、人物、环境和经历是否被准确标注，未被表达性生成伪装。
- 是否出现新的问题：风格压过内容、细节失真、边缘破坏、语义误读、品牌不一致或阅读负担增加。

结果分为：

- **通过**：主问题得到解决，副作用在可接受范围内，可以交付。
- **部分通过**：方向成立，但需要一次针对性迭代。
- **不通过**：主问题未解决或新风险更大，应回到诊断或更换策略。
- **阻塞**：缺少素材、权限、工具、关键上下文或用户决定，停止继续改造。

## 阶段六：迭代与停止

每轮迭代只改变一个主要变量或一组有因果关系的变量，并记录：

- 本轮要解决的问题。
- 采用的策略和能力。
- 相对上一版的具体变化。
- 评价结果和新问题。
- 下一轮继续、换策略、请求确认或停止的理由。

### 降级与停止条件

满足以下任一条件时停止或降级：

- 主任务已通过，继续修改只会增加风格偏好而非实际收益。
- 连续两轮没有改善主问题，说明诊断或策略需要重做。
- 新增的真实性、语义或技术风险超过收益。
- 缺少用户必须确认的内容，不能自行替代。
- 达到用户约定的轮数、时间或成本边界。
- 当前等级无法解决问题，应回到上一级或重新诊断。

**降级规则**：
- L4 无法解决 → 回到 L3 或重新诊断
- L3 无法解决 → 回到 L2 或重新诊断
- L2 无法解决 → 回到 L1 或重新诊断
- L1 无法解决 → 停止并说明原因

## 输出契约

除非用户只要求一个简短判断，否则输出以下结构：

1. **素材判断**：事实观察、主问题、次问题、潜力和不确定性。
2. **缺失分析**：缺失类型、可恢复性、推荐等级和理由。
3. **视觉任务**：受众、媒介、目标状态和成功标准。
4. **策略选择**：主策略、可选辅助策略、选择理由、代价和禁用项。
5. **能力计划**：调用的能力类别、输入、保留项、输出和 fallback。
6. **决策契约**：完整的 JSON 决策结构。
7. **结果评价**：相对原图的变化、通过项、未解决项和真实性边界。
8. **下一步**：继续迭代、换策略、降级、请求用户确认或停止。

如果需要实际执行，先给出最小策略摘要；完成后补充结果评价和下一步，不要把未执行的计划写成已完成事实。

## 摄影师级判断标准

不要把技术标准等同于审美标准。以下情况可能是缺陷，也可能是表达：

- 阴影重
- 颗粒明显
- 运动模糊
- 留白大
- 构图不对称
- 色彩偏移
- 主体不完全清晰
- 空间不写实

**判断原则**：
1. 先判断是否服务目标
2. 再判断是否可能是有意选择
3. 最后决定是否需要处理

## 安全边界

- 不把表达性生成的元素描述成原照片中真实存在的事实、人物、地点、事件或个人经历。
- 涉及身份、隐私、敏感场景、未成年人、医疗、灾害、新闻或公共证据时，先标注真实性要求和可改造范围；无法确认时停止生成性重构。
- 不移除会改变关键事实判断的内容后，再把结果用于证明、取证、新闻、研究或商业声明。
- 涉及公开发布、版权不明素材或他人肖像时，先确认使用权限和发布边界。

## 需要现场确认的信息

对工具名称、模型版本、文件路径、输出尺寸、运行环境、授权状态和可用能力，先通过当前环境或用户提供的信息确认；不要把历史观察值写成永久事实。

## 人像处理能力

当用户提供人物照片（少女、女性、男性、儿童或其他人物）并希望提升质感、去除瑕疵、增强美感或营造特定气质时，见相具备专业的人像处理能力。

### 人像处理的判断顺序

1. **先确认任务与边界**：照片用途、目标气质、希望保留的特征、允许的改造范围、真实性模式、目标媒介。
2. **再做事实观察**：人物位置、比例、姿态、视线、面部受光、皮肤纹理、头发服装、背景关系。
3. **区分可修瑕疵和真实特征**：临时性瑕疵可修，稳定外观特征不默认移除。

### 人像处理的四层技术路径

| 等级 | 名称 | 典型处理 |
|------|------|----------|
| L1 | 基础显现 | 曝光、白平衡、肤色、降噪、锐化、抑制手机感 |
| L2 | 人像关系重构 | 裁切、人物位置、视线留白、背景清理 |
| L3 | 人像审美增强 | 光影塑形、肤色协调、情绪放大、系列统一 |
| L4 | 表达性或生成性重构 | 背景生成、空间补全、光线重建 |

### 朦胧感的四种类型

用户说想要朦胧感时，先判断是哪一种：

- **光学朦胧**：逆光、散射光、高光扩散
- **空气朦胧**：雾、空气透视、远近层次
- **质感朦胧**：柔焦、轻微纹理扩散、低反差
- **色彩朦胧**：低饱和、柔和色阶、相邻色关系

### 人像安全边界

- 不改变人物身份、面部结构或关键生理特征
- 不把标准化审美当作默认质量标准
- 不把稳定外观特征自动视为瑕疵
- 纪实模式下禁止生成性改变

详细的人像处理指南，请读取 `references/portrait-craft.md`。

## 运行时能力

本 Skill 具备最小真实执行能力，支持以下运行时操作：

### 能力分级

| 等级 | 名称 | 说明 |
|------|------|------|
| V0 | 文件访问 | 核心运行时默认可用：读取图片、获取尺寸、计算 SHA-256 |
| V1 | 视觉观察 | 外部观察 adapter 按现场启用；默认不提供，必须有可执行、可校验的结构化观察路径 |
| V2 | 图像编辑 | 核心运行时提供有限的 L1/L2 确定性操作（内置 Pillow）；不代表 L3/L4 |
| V3 | 结果比较 | 核心运行时提供 local-compare 工程比较；不代表审美判断或用户确认 |

### 内置确定性编辑能力

**L1 曝光/对比度/饱和度**：
- `exposure`: -1.0 到 1.0
- `contrast`: 0.5 到 1.5
- `saturation`: 0.5 到 1.5

**L2 裁切**：
- 绝对坐标 `(left, upper, right, lower)`
- 必须在图像范围内

**L2 调整大小**：
- `width`/`height`: 正整数，最大 8192
- `fit`: "contain" 或 "cover"

### 运行时入口

```powershell
# 运行单案例
.\.venv\Scripts\python.exe skills\visual-art-direction\scripts\runner.py `
  --case .skill-work\real-cases\case-001\runtime\case.json `
  --output .skill-work\real-cases\case-001\runtime\output
```

### 能力状态与降级

- `ready`: 能力探测通过
- `blocked_no_input`: 输入文件不存在
- `blocked_no_view_capability`: 无 V1 能力
- `blocked_no_edit_capability`: 无 V2 能力
- `blocked_no_comparison_capability`: 无 V3 能力
- `blocked_no_candidate`: 无候选图
- `completed_with_user_confirmation_pending`: 执行完成，等待用户确认
- `completed`: 执行完成，用户已确认
- `failed_invalid_contract`: 契约校验失败
- `failed_execution`: 执行过程失败

### 真实证据要求

- V0: 文件存在、Pillow 可识别、SHA-256 计算成功
- V1: adapter 必须有真实 `observe(image, prompt)` 执行路径，并返回 schema-valid 观察结果
- V1: 观察结果必须绑定输入图片 SHA-256 和本次 prompt SHA-256
- V1: malformed、adapter exception 或 hash mismatch 必须 fail-closed
- V2: 内置 deterministic-pillow 只证明 L1/L2；外部 adapter 必须同时具备健康证据和实际执行路径
- V3: 内置 local-compare 只证明工程差异报告；不能把它写成审美质量通过
- adapter 名称本身不能让能力变成 true

详细运行时契约，请读取 `references/runtime-contract.md`。
